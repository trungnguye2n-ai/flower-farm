# Vườn hoa — Phase 1: Database & Docker Infra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Next.js app skeleton backed by a production-grade Postgres schema (migrations, seed, admin CLI, auth core, image storage) and a Docker setup that runs locally today and on a VPS later with the same images.

**Architecture:** One Next.js (App Router, `output: 'standalone'`) app at the repo root. Drizzle ORM owns the schema; drizzle-kit generates versioned SQL migrations that a one-shot `migrate` container applies before `app` starts. Images go to MinIO through the generic S3 SDK. `compose.yaml` holds the shared services; `compose.dev.yaml` and `compose.prod.yaml` override per environment (prod adds Caddy for HTTPS).

**Tech Stack:** Node 24, Next.js 16, TypeScript, Drizzle ORM + drizzle-kit, `postgres` (postgres.js), Postgres 18, MinIO (`cgr.dev/chainguard/minio`), `@aws-sdk/client-s3`, `@node-rs/argon2`, zod, vitest, tsx, Docker Compose, Caddy 2, GitHub Actions + GHCR.

**Spec:** `docs/superpowers/specs/2026-11-02-vuon-hoa-app-design.md`

## Global Constraints

- Node 24 LTS in every image and in CI; Postgres 18; Next.js 16 App Router with `output: 'standalone'`.
- Money is an integer number of **đồng** (`integer`, `CHECK (price >= 0)`); never float/numeric with decimals.
- Schema changes only through drizzle-kit generated migrations committed under `drizzle/`; never hand-edit a live DB.
- Every secret comes from env; `.env` is gitignored; `.env.example` lists every variable with a placeholder. No default admin password anywhere.
- Containers run as a non-root user; every long-running service has a healthcheck; named volumes for `pgdata`, `miniodata`, `backups`, `caddy_data`.
- Image source for MinIO: `cgr.dev/chainguard/minio` and `cgr.dev/chainguard/minio-client` (user decision: keep MinIO; Docker Hub `minio/minio` no longer publishes). Pin by digest in `compose.yaml`.
- Soft delete (`deleted_at`) on `products` and `product_variants`; all reads exclude soft-deleted rows.
- Exactly one primary image per product, enforced by the database.
- User-facing copy (CLI messages, health JSON keys excepted) is Vietnamese.
- Out of scope for this phase: landing/admin UI, order submission endpoint, image resizing pipeline, Zalo integration.

## Review Focus

- **Seed or migrate run twice** (container restarts) → no duplicate rows, no error. Pinned in Task 5 (`seed is idempotent`) and Task 9 (migrate service re-run).
- **Product deleted after it was ordered** → old orders keep name, variant name and price. Pinned in Task 4 (`order_items keep snapshot when product is hard-deleted`).
- **Second primary image for the same product** → rejected by the DB, not silently accepted. Pinned in Task 4.
- **MinIO or Postgres down** → `/api/health` answers 503 with which dependency failed, the app process stays up. Pinned in Task 8.
- **`docker compose down` then `up`** → data and images survive. Pinned in Task 9 verification and Task 10 restore test.

### Task 4: Schema and first migration

**Files:**
- Create: `src/db/schema.ts`, `src/db/client.ts`, `src/db/migrate.ts`, `drizzle.config.ts`, `drizzle/0000_*.sql`, `tests/helpers/db.ts`, `tests/schema.test.ts`

**Interfaces:**
- Produces tables (Drizzle export names in parentheses): `categories` (`categories`), `products`, `product_variants` (`productVariants`), `product_images` (`productImages`), `admin_users` (`adminUsers`), `sessions`, `site_settings` (`siteSettings`), `orders`, `order_items` (`orderItems`); enum `order_status` = `new | confirmed | delivered | cancelled`.
- Produces: `createDb(url: string): { db, sql }` in `client.ts`, `db` default instance from `env.DATABASE_URL`; `runMigrations(url: string): Promise<void>` in `migrate.ts` (also runnable as script); test helper `freshTestDb(): Promise<Db>` that drops and recreates the `public` schema in `vuonhoa_test` then runs migrations.

Columns per spec §4, with these pinned details:
- All ids `uuid` default `gen_random_uuid()`; timestamps `timestamptz`, `created_at`/`updated_at` default `now()`.
- `categories.care`: `jsonb` array of `{ title: string, body: string }`; `slug` unique.
- `products`: `category_id` FK `ON DELETE RESTRICT`; `slug` unique among non-deleted rows (partial unique index `WHERE deleted_at IS NULL`); `accent_color` `CHECK (accent_color ~ '^#[0-9A-Fa-f]{6}$')`; `is_visible` default true.
- `product_variants`: FK `ON DELETE CASCADE`; `price integer NOT NULL CHECK (price >= 0)`; `in_stock` default true.
- `product_images`: FK `ON DELETE CASCADE`; partial unique index on `(product_id) WHERE is_primary`; `storage_key` unique.
- `sessions`: `token_hash text` unique (store SHA-256 of the token, never the token), `admin_user_id` FK `ON DELETE CASCADE`, `expires_at`.
- `admin_users.email` unique on `lower(email)`.
- `site_settings`: single row enforced by `id integer PRIMARY KEY CHECK (id = 1)`; columns `shop_name`, `phone`, `zalo`, `hours`, `delivery_area`, `address`.
- `orders`: `code text` unique, `total integer CHECK (total >= 0)`, `status order_status default 'new'`; index on `(status, created_at desc)`.
- `order_items`: `order_id` FK `ON DELETE CASCADE`; `product_id` and `variant_id` FK `ON DELETE SET NULL`; snapshot columns `product_name`, `variant_name`, `unit_price integer CHECK (>= 0)`, `quantity integer CHECK (quantity > 0)`.
- `updated_at` maintained by a trigger function `set_updated_at()` on every table that has the column (add as custom SQL in the generated migration).

- [ ] **Step 1:** Write `tests/schema.test.ts` (each test calls `freshTestDb()`):
  - `migrations apply to an empty database` — `select count(*) from drizzle.__drizzle_migrations` ≥ 1.
  - `rejects negative price` — insert variant with `price: -1` rejects with code `23514`.
  - `rejects second primary image` — two `is_primary: true` images for one product, second rejects with `23505`.
  - `slug can be reused after soft delete` — soft-delete product `slug: 'a'`, insert another `'a'` succeeds; inserting a third live `'a'` rejects `23505`.
  - `order_items keep snapshot when product is hard-deleted` — create order item, `delete from products`; item remains, `product_id` null, `product_name` and `unit_price` unchanged.
  - `cannot delete category that still has products` — rejects `23503`.
  - `updated_at changes on update` — update product name, `updated_at > created_at`.
  - `site_settings allows one row only` — inserting `id: 2` rejects.
- [ ] **Step 2:** Run `npm test tests/schema.test.ts` → FAIL.
- [ ] **Step 3:** Write `schema.ts`, `drizzle.config.ts`; `npm run db:generate`; append the trigger SQL to the generated migration via `drizzle-kit generate --custom` as a second migration `0001_updated_at_triggers.sql`.
