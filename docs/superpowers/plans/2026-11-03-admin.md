# Vườn hoa — Phase 2a: Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A logged-in `/admin` where the garden's people manage flower categories, products, variants, prices, stock and photos, follow the order log and edit the shop's contact info, from a phone standing in the garden or from a laptop.

**Architecture:** Business logic lives in plain modules under `src/admin/`, `src/auth/` and `src/images/` that take a `Db` (and a storage port for images) and are tested with vitest against the test database and dev MinIO. Next.js pages and Server Actions under `src/app/admin/` are thin: `requireAdmin()`, call the module, `revalidatePath('/')`, return a `Result`. Photo uploads use one route handler (Server Actions cap bodies at 1 MB) with its own Origin check; sharp resizes to WebP on the server, and the browser converts HEIC and shrinks very large photos before sending.

**Tech Stack:** Existing phase-1 stack plus `sharp` (0.35), `motion` (14, springs/drag/reorder), `heic2any` (browser HEIC → JPEG, loaded only for HEIC files), `@playwright/test` (one end-to-end smoke). `next/font/google` for Bricolage Grotesque.

**Spec:** `docs/superpowers/specs/2026-11-02-vuon-hoa-app-design.md` (§4, §5, §7, §9). Landing page, order submission and demo copy (§8) are plan 2b.

## Global Constraints

- Every `/admin` page and every Server Action or route that writes calls `requireAdmin()` on the server; `src/proxy.ts` only does an optimistic cookie-presence redirect.
- Session cookie `vh_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` when `APP_URL` starts with `https:`, expires with the session.
- CSRF: Server Actions rely on Next's built-in Origin-vs-Host check; the upload route uses `checkOrigin()` (same rule). No GET request changes data.
- Login rate limit: within 15 minutes, 5 failures per email or 20 per IP block further attempts; error copy "Đăng nhập sai quá nhiều lần. Thử lại sau 15 phút." Wrong credentials always answer "Sai email hoặc mật khẩu" (no hint whether the email exists).
- Money is integer đồng. Admin price input accepts `150000`, `150.000`, `150,000`, `150.000đ`, `150k`; anything else is a field error "Giá không hợp lệ".
- A product always has at least one live variant ("Cần ít nhất một kiểu bán"). Deleting a product or variant is soft; product delete can be undone for 10 s from a toast and later from "Đã xoá" filter.
- Images: accept JPEG, PNG, WebP after HEIC conversion in the browser; max 15 MB per file on the server ("Ảnh lớn hơn 15 MB"); output WebP widths 480, 960, 1920 (never enlarged), EXIF orientation applied then all metadata dropped, 16 px blur placeholder as a data URL. Keys `public/products/<productId>/<imageId>-<width>.webp`; `product_images.storage_key` stores `public/products/<productId>/<imageId>`.
- Images are rendered with plain `<img srcset>` (already resized), not `next/image`.
- Look: same tokens as `legacy/index.html` (Bricolage Grotesque, `--stage #1E3644`, `--paper #F5F6F7`, `--text #1B1B1F`, `--muted #5D5E66`, `--line #DCDDE2`, dark-mode values, glass with `backdrop-filter: blur() saturate(180%)` and a no-blur fallback). Motion per apple-design: springs, interruptible, sheet drag-to-dismiss, press scale 0.96, `prefers-reduced-motion` respected. Stageshow rules for state: the Save button changes to "✓ Đã lưu" on itself; errors show under the field that caused them.
- Layout: bottom sheet under 900 px wide, right side panel at 900 px and up. Touch targets ≥ 44 px. Works at 360 px wide.
- All copy Vietnamese. No `confirm()`/`alert()`.
- Out of scope: landing page, public order endpoint, Zalo API, password reset UI, roles.

## Review Focus

- **Forged, expired or revoked session cookie** → every admin page redirects to `/admin/login` and every write is refused, including direct POSTs to the upload route. Pinned in Task 1 (`currentAdmin` cases), Task 5 (guard test over all admin files) and Task 9 (e2e).
- **Price typed the Vietnamese way** (`150.000`, `150k`, `150.000đ`) → stored as 150000; `-5`, `abc`, `1.5` → field error, nothing saved. Pinned in Task 2.
- **8 MB iPhone portrait with EXIF orientation 6 and GPS** → stored upright, no GPS or EXIF, ≤ 1920 px, served as WebP. Pinned in Task 3.
- **Upload fails halfway** (storage or database error) → no `product_images` row pointing at missing files and no orphan files left. Pinned in Task 3.
- **Removing the primary photo or the last variant** → another photo becomes primary; last variant removal is refused with a field error. Pinned in Tasks 2 and 3.
